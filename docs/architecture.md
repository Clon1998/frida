# Architecture

A map of the code for contributors: which crate does what, how a send flows through the system and how to add a
feature end to end. The rules behind this layout are in [CLAUDE.md](../CLAUDE.md) and [PLAN.md §3](../PLAN.md#3-repository-layout).

## The big picture

```
┌──────────────────────────── app/ui (React + TS) ────────────────────────────┐
│ components/*  ── Zustand stores (stores/*) ── commands.* from bindings.ts   │
└───────────────────────────────────┬─────────────────────────────────────────┘
                                    │ Tauri IPC (JSON), types generated by tauri-specta
┌───────────────────────────────────▼─────────────────────────────────────────┐
│ app/src-tauri: thin #[tauri::command] functions + AppState (in-memory state) │
└───────┬─────────────────┬──────────────────┬─────────────────┬──────────────┘
        ▼                 ▼                  ▼                 ▼
   frida-core        frida-secrets       frida-git        frida-script
   (everything        (keychain, file,    (system git,     (QuickJS sandbox,
   about requests)    AWS Secrets Mgr)    allow-listed)     fri/req/res API)
        └── uses frida-script and frida-secrets
```

- **The UI never touches the network, files, git or secrets.** It calls a command and renders the result.
- **The crates never depend on Tauri.** They can be tested with plain `cargo test` and reused by the planned CLI
  (PLAN.md M15).
- `app/src-tauri` only translates: it reads the arguments, finds the open workspace in `AppState`, calls a crate
  and maps errors to an `ApiError`.

## How a send works

`commands::http::send_request` (app) → `frida_core::http::execute` (core):

1. **Load the context**: `collection.yaml`, the folder chain from the collection root down to the request, and the
   request as currently edited (unsaved changes are sent, too).
2. **Environments**: the app loads the active global and collection environments and fills in secret values from
   the keychain (`spawn_blocking`) and AWS (cached). Script overrides from this session (`fri.setEnvVar`) are applied.
3. **Pre-request scripts**: collection → folders → request, each in its own sandbox. They see the request *before*
   variables are resolved and may change it.
4. **Resolve variables** across the six layers (§5). The result also contains a `ResolveReport` for the inspector
   and the list of secret values, used for masking later.
5. **Prepare**: merge headers (collection → folder → request), build the URL, body and settings.
6. **Auth**: apply the effective auth schemes; OAuth2 fetches or refreshes a token if needed.
7. **Send** with reqwest (cookie jar per collection, custom CAs, timeout, cancellation token).
8. **Post-response scripts and tests**: request → folders → collection.
9. Back in the app: the console entry and history entry are written **with secrets masked**, the full body goes
   to an in-memory response cache, and a `ResponseView` (a size-limited, displayable version) goes to the UI.

The **inspector** uses the same code up to step 4 (`http::inspect`), without running scripts or sending.
The **runner** calls the same pipeline per request (`http::execute_as` with `ExecutionMode::Runner`).

## State

- **On disk, shared**: the YAML files (see [file-format.md](file-format.md)).
- **On disk, per machine**: `LocalStore` (`settings.json`, `state/<collection id>.json`), `history.sqlite`, logs.
- **In memory** (`app/src-tauri/src/state.rs`, `AppState`): the open workspace, in-flight requests (for cancel),
  the response cache, one `SessionStore` per collection (runtime variables, environment overrides), cookie jars,
  OAuth2 tokens, the AWS cache and the secret store.

`AppState` is shared by commands that run concurrently, so mutable fields sit behind a `std::sync::Mutex` (never
held across an `.await`) and values that must outlive a lock are wrapped in `Arc`.

### The secret store stack

Secret stores are decorators around one trait, `SecretStore`, built once at startup (`state.rs`, `os_keychain`):

```
CachedStore                          each secret read at most once per run
 └── macOS, signed app:   MigratingStore(ProtectedStore → VaultStore → old per-secret items)
     macOS, unsigned dev: MigratingStore(VaultStore → old per-secret items)
     Windows / Linux:     KeychainStore
No keychain at all:  EncryptedFileStore (secrets.enc, password)
```

## Rust ↔ TypeScript

- Commands are `#[tauri::command] #[specta::specta]` functions in `app/src-tauri/src/commands/*.rs`, registered
  in `specta_builder()` in `app/src-tauri/src/lib.rs`.
- tauri-specta generates `app/ui/src/bindings.ts` (`commands.*`, `events.*` and every model type) on each debug
  start and on `cargo test`. CI fails if the committed file is stale. **Never write these types by hand.**
- Commands return `Result<T, ApiError>`, which becomes `{ status: "ok", data } | { status: "error", error }` in TS.
  `unwrap()` in `app/ui/src/lib/api.ts` turns that into a value or a thrown `FridaError`; `showError()` shows the
  message and hint as a toast.
- Rust → UI pushes use typed events: `FsChanged` (files changed on disk), `ConsoleLogged`, `ScriptLogged` and the
  runner's `RunProgress`.
- Fields with `#[serde(default)]` are optional in the generated TS. The UI converts values from Rust once with
  `Complete<T>` (`app/ui/src/lib/model.ts`).

## Errors

- Library crates define `thiserror` enums (`CoreError`, `SendError`, `SecretError`, `GitError`, `AwsError`, …).
- `app/src-tauri/src/error.rs` maps each of them to an `ApiError { code, message, hint, aws }`. The `code` is a
  stable enum the UI can switch on (e.g. `aws_profile_required` opens the profile dialog); the `hint` says what
  the user can do.
- Error messages never contain secret values.

## Adding a feature end to end

Say you want a new command `count_requests(dir)`:

1. Write the logic in a crate, e.g. `frida_core::storage::count_requests`, with unit tests next to it or an
   integration test in `crates/frida-core/tests/`.
2. Add a thin command in `app/src-tauri/src/commands/collection.rs`:
   ```rust
   #[tauri::command]
   #[specta::specta]
   pub async fn count_requests(state: State<'_, AppState>, dir: String) -> ApiResult<u32> {
       let dir = state.collection_dir(&dir)?;
       blocking(move || Ok(storage::count_requests(&dir)?)).await
   }
   ```
   File I/O, SQLite, keychain and git calls go through `blocking` (`spawn_blocking`) so they don't stall the
   async runtime.
3. Register it in `collect_commands![…]` in `app/src-tauri/src/lib.rs`.
4. Run `cargo test -p frida-http` (or start the app) to regenerate `bindings.ts`.
5. Call it from a store: `const n = await unwrap(commands.countRequests(dir));`.
6. If the Playwright flows touch it, add it to the fake backend in `app/ui/src/e2e/fakeBackend.ts`; the e2e fixture
   fails on unhandled commands.

## Tests

| Layer | Where | Run with |
|---|---|---|
| Unit tests | `#[cfg(test)] mod tests` next to the code | `cargo test --workspace` |
| Integration tests | `crates/*/tests/*.rs`, often against `frida-testserver` on a random port | `cargo test --workspace` |
| Snapshots | `insta`, in `crates/frida-core/tests/snapshots/` (importers, curl, file format) | `cargo insta review` after a change |
| Git | Temporary repos with a local bare remote (`crates/frida-git/tests/repo.rs`) | `cargo test -p frida-git` |
| UI units | Vitest, `*.test.ts(x)` next to stores and utilities | `pnpm test` in `app/ui` |
| UI flows | Playwright against Vite with a fake backend (`app/ui/e2e`), Chromium and WebKit | `pnpm e2e` in `app/ui` |

Fixtures live in `testdata/`. More on running them in [development.md](development.md).
